💡 Hallazgos clave — Q4_K_M vs Q8_0 cache vs Speculative

  • Q8_0 cache-type es el ganador claro: --cache-type-k q8_0 y --cache-type-v q8_0 con ubatch-size 256 domina ambos prompts. En prompt 1 (respuesta larga), reduce el tiempo de 1,159s → 256s (-78% 🔥)
  • ubatch 256 > ubatch 128 para Q8_0: en prompt 1, ubatch 256 es 32% más rápido que ubatch 128 (255.9s vs 375.7s). En prompt 2 también gana pero la diferencia se achica (+1.7% vs baseline).
  • Speculative decoding NO funciona bien con este modelo: draft acceptance rate de solo 9.4% (prompt 1) y 6.8% (prompt 2). Es decir, genera ~64 tokens por cada 6 que acepta — es contraproducente.
  • Q4_K_M cache produce MUCHO más texto pero tarda exponencialmente más: prompt 1 generó 30,939 tokens vs ~8,300 de las otras configs. Si necesitás respuestas largas, el gap de velocidad se reduce pero no desaparece.
  • Prompt 2 (más corto): la diferencia entre Q4 y Q8_0 ubatch256 es mínima (+1.7%). Para tareas WordPress cortas (<~8K tokens), la elección de cache-type importa menos.
  • Prompt 1 (largo): la diferencia es brutal (-78% con Q8_0 ubatch256). Para respuestas extensas (CPT completos, migrations, etc.), la config de cache-type es CRÍTICA.
